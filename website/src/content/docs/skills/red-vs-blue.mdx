One finding, one fight. Red argues the finding is real and finds the input
that breaks the code. Blue reproduces it or refutes it. The gate scores what
is left. A review comment goes in; one word comes out: Survives or Falls.
Pictured as Rock 'Em Sock 'Em Robots: two fighters built the same, told to
win opposite fights.

## The dunky way

- **One finding, one fight.** A PR comment never turns into a thread of
  agents arguing. It gets one fight, settled with evidence.
- **Green is not safe, and neither is "seems fine".** Red climbs the
  evidence ladder in `standards/severity.md`: point at the line, walk the
  path, run it. Blue needs the same kind of evidence to refute.
- **The repo wins.** A rule in `AGENTS.md` or a `SPEC.md` that makes the
  behavior intended ends the fight: the finding falls as intended.
- **Same model, opposite mandates.** The signal comes from the fight, not
  from either side being smarter.

<Fragment slot="with">

**Finding.** `greet('')` returns `Hello, !`. Where: `src/greet.ts`.

**Red.** Could not make it concrete. The empty string is handled before the
template.

**Blue.** Refuted. `src/greet.ts:2` returns `Hello, stranger!` for `''`.
Ran it: `greet('')` gives `Hello, stranger!`.

**Gate.** Confidence 5. Severity: none. **Falls.**

## Call it

Say "red vs blue this", "fight this finding", or "is this comment real?".
Or type `/red-vs-blue "<comment>"`, and add `--cross` to run Red on a second
model family. Read the
[skill README](https://github.com/dunky-dev/skills/tree/main/skills/red-vs-blue).
