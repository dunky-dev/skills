Six ways to vibe-test a skill.

Every option answers the same question: given a prompt, does the agent behave better with the skill installed than without it? They differ in who runs the loop, what can be checked, and what you install. Names withheld on purpose. Judge the mechanism.

Facts from the tools' own docs and repos, fetched 2026-10-19. Maturity is described, not counted. Nothing here is our own measurement.

Same for all
A scenario is a prompt, two or more conditions, and a grader. Baseline must fail, skill must pass.
Differs
Who orchestrates: an agent, a config runner, a binary, a harness, or your shell.
Hard part
Proving the skill actually fired. Only options that see the tool trace can.
Your constraints
No node toolchain. More than one harness. Markdown and sh.
01 · Anatomy

What every option runs

Strip the tooling and the shape is identical. Five nodes. The options only change who owns each node and how much of it is code.

01

Scenario

A naive prompt that describes the outcome, never the solution. A fixture repo to run in. The skills to install.

02

Conditions

Baseline: no skill. Treatment: skill installed. Optional: second harness, second model.

03

Isolated runs

One fresh agent per prompt × condition. Fresh temp dir, no inherited memory. Same prompts in every arm.

04

Graders

Scripted checks for anything objective: file named, line cited, tool called. A separate judge for the fuzzy part.

05

Report

A table: scenario × condition. Delta between arms. Stored JSON if you want trends. Exit code for CI.

The honest-delta rule: a check that can only pass with the skill, like "the skill fired", must not count against the baseline. Otherwise the delta is inflated by construction.

04 · Rules that hold everywhere

Borrowed from the people who run this nightly

Same prompts, always

Sample the battery once. Every condition sees the identical prompts. Five to fifteen prompts: easy, differentiating, edge, coverage-gap.

Isolation or nothing

One agent per prompt × condition, spawned fresh. Contamination signs: zero hallucinations, near-identical scores across arms, uniform confidence, one agent doing several arms in sequence.

Never self-judge

Runners self-report approach and doubts. A separate judge sees all arms side by side and scores on one scale. Judge is never the model under test.

Script the objective

If a check can be a regex or a file test, it is. The judge is reserved for what cannot be scripted. Deterministic checks are free and never flaky.

Patterns, not nights

Act on a failure that repeats across runs. Fixing one bad night overfits. Store JSON per run if you intend to compare.

Trigger is its own test

Whether the skill fires depends on the description alone. Test it separately with should-fire and should-not-fire prompts, before testing what the body does.
