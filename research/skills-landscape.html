Research brief · 2026-10-15

Three agents, one spec-driven loop.

What the best public skill sets do, where they break, and how Scout, the Oracle, and Red / Blue fit the SPEC -> TEST -> IMPLEMENT -> RECONCILE state machine in every dunky repo.

Sources: raw SKILL.md files, issue trackers, and author posts fetched on 2026-10-15. Star counts are as shown on GitHub that day. Nothing here is a measurement of our own.

Scout
Fork of Pocock's wayfinder. Charts fog into decision tickets. Never builds.
Oracle
Fork of Pocock's grilling. Asks the frontier in rounds. Sits with you in every phase.
Red / Blue
Tower defense at RECONCILE. Red attacks through a power. Blue must refute or reproduce. A gate scores survivors.
Powers
Pluggable lenses as references/<power>.md. Nobody ships this abstraction yet.
Verdict

Copy Pocock's shapes. Borrow poteto's verification discipline. Build the plug yourself.

Keep from Pocock

  • One-line user-invoked wrappers over model-invoked primitives.
  • Frontier rounds with a recommended answer per question.
  • Decision tickets on the tracker, not in context.
  • The no-op test: delete any line the model already obeys.

Keep from poteto

  • "Green is not safe." The agent that judges never wrote the change.
  • Lead judgment sorts findings into Act on / Consider / Dismissed.
  • Fix repeated mistakes at the highest level: code > lint > skill text.
  • Every skill ends with a Reply: contract.

Avoid

  • Adversarial review of abstract plans. Both authors report hallucinated risk.
  • Self-authorizing notes in the Scout map (wayfinder issue #683).
  • Descriptions that summarize the workflow. The model acts on the summary and skips the body.
  • Persona-only diversity. Pair it with mandate or model diversity.

Build new

  • The power plug: one routing table, one file per lens.
  • Two dunky-only powers: spec fidelity against SPEC.md, and twin parity (TS vs Rust).
  • Skills follow the same loop: SPEC.md, eval scenarios, SKILL.md, skill-doctor.

02 · Matt Pocock

wayfinder and grilling, in depth

His skills are small, second-person, imperative. A user-invoked skill may call model-invoked skills, never another user-invoked one. Em-dashes and "be thorough" lines are banned as no-ops.

"Plan, don't do. Each ticket resolves a decision, and the map is done when the way is clear, with nothing left to decide before someone goes and does the thing."wayfinder/SKILL.md

When

A loose idea too big for one agent session, "wrapped in fog". The split from grill-with-docs is session count, not project size. It is a situational on-ramp, not the default start.

The Map

One tracker issue labelled wayfinder:map. An index, not a store. Sections: Destination, Notes, Decisions so far, Not yet specified (the fog of war), Out of scope.

Decision tickets

Child issues with one ## Question, sized to one 100K-token session. One type label each: research (AFK, subagent), prototype (HITL), grilling (HITL, default, also loads domain-modeling), task (the one type that does). Claim = assignee. Frontier = open, unblocked, unclaimed.

Chart

  1. Name the destination (grilling + domain-modeling).
  2. Map the frontier, breadth-first. No fog means no map: stop and ask.
  3. Create the map issue.
  4. Create tickets, then wire blocking edges in a second pass with real ids.
  5. Fire research subagents in parallel.
  6. Stop. Charting resolves nothing.

Work

Load the map at low resolution. Pick the user's ticket or the first on the frontier. Claim it. Resolve by type. Post a resolution comment, close, append a pointer to Decisions so far. Create newly surfaced tickets. Never resolve more than one ticket per session, except research.

Fog vs ticket

The test is "whether you can state the question precisely now, not whether you can answer it now."

Hand-off

When the map clears: /to-spec #<map>, then /to-tickets, then /implement. Wayfinder cannot call these itself because they are user-invoked.

gapSelf-authorized execution

Issue #683. An agent wrote "This map carries execution" into Notes. Later sessions read it as their own licence and built on a live server. Docs admit "the skill has no hard stop for 'I meant the default'."

Scout fix: the Notes section cannot grant execution. Scout has no write path to code at all.

gapSizing checked once

Issue #888. Tickets grew through appended Update blocks. One session burned over 300k tokens.

Scout fix: re-size on claim. If the ticket outgrew a session, split before resolving.

gapGrilling contradiction

Issue #1093. Grilling says "do not act until the user confirms". Wayfinder says close the ticket. Jointly unsatisfiable for weaker models.

Scout fix: the Oracle ends a round with an explicit confirmation line. Scout closes only after it.

gotchaWaterfall drift

Author: "I charted 27 tickets, and by the time I got to the thirteenth, the rest no longer made sense." Advice: bound the destination to one epic. "Wayfinder is prototypemaxxing, not planmaxxing."

Scout fix: cap the first chart. Prefer prototype tickets over grilling tickets when a question is answerable by running code.

gotchaVerbosity

"Every question is three paragraphs long. Nobody has fixed it yet." Issue #1180: ADR and ticket numbers dilute attention.

Oracle fix: one sentence per question, one line per recommendation. Refer by name, never by number.

gotchaParallel sessions re-ask

Sessions share no context, so they repeat questions. A prototype agent once built three UI variants, chose one itself, and closed the ticket.

Scout fix: HITL ticket types cannot close without a user line in the thread.

gotchaWrong closed decision

"No official guidance. It tends to design around the bad decision instead of challenging it."

Scout fix: a reopen move with a new-evidence requirement, borrowed from contrarian's settled ledger.

openOther open issues

#492 cannot invoke /to-spec. #599 remote changes by default. #556 skips domain-modeling. #941 research only fires at charting. #1020 throwaway branches pile up. #1282 maps hide decision context from new sessions. Local-markdown trackers are "not recommended, because material stored in the repo tends to persist by accident."

grill-me is one line: Call the Skill tool with "grilling". The primitive is grilling. grill-with-docs adds domain-modeling for a glossary and ADRs.

"Map this as a design tree. The frontier is every decision whose prerequisites are already settled. Ask the whole frontier in one round: number each question and give your recommended answer. Then wait."grilling/SKILL.md

Rounds, not one-at-a-time

Changed in v1.1. "Same 13 questions land in ~3 rounds instead of 13." Dependent questions go to a later round. Opt-out: add "When grilling, ask one question at a time." to CLAUDE.md.

Format

❓ Q1 - Tracker: Where do Scout maps live?
➡️ GitHub issues. Every dunky repo is already on GitHub and you use gh.
---
❓ Q2 - ...

"Word each question so yes accepts your recommended answer."

Facts vs decisions

"Finding facts is your job, never the user's. Dispatch a sub-agent. Don't block on it. The decisions are the user's: put each to them and wait."

Stop condition

"The session is done when the frontier is empty. Do not act on it until the user confirms you have reached a shared understanding." Output is nothing on disk. Hand the same conversation to to-spec without clearing.

Rejected on purpose

No AskUserQuestion UI. No question caps ("Codex just asked me 200 questions" stays out of scope). "Forty-six questions across four rounds is an ordinary session."

Known bugs

Dependency skills not loading. Weaker models skip the confirmation gate (#975, #1068). Numbering restarts (#1154). The agent answers its own questions when run inside another skill.

Frontmatter

name, description, optional disable-model-invocation: true, rare argument-hint. Sibling agents/openai.yaml for Codex. Rule: "a skill is user-invoked in both harnesses or neither."

Two buckets

User-invoked: human-facing one-liner, no triggers. Model-invoked: "Use when..." with trigger phrases. Invariant: user-invoked may call model-invoked, never another user-invoked.

Length

One line to ~150 lines. "A 400-line skill still leaves the model verbose." Steps carry a "Done when..." completion criterion.

Doctrine: writing-for-agents

  • Two loads. Context load and cognitive load. The second is the price of human agency.
  • Context pointers. The pointer's wording decides when the agent reaches the material.
  • Leading words. Compact concepts from pretraining: tight, red, tracer bullets.
  • No-op test. An instruction the model already obeys costs load and says nothing. Delete it.
  • Prompt the positive. "Don't think of an elephant" fails.

Flow he teaches

grill-with-docs -> prototype -> to-spec -> to-tickets -> implement (tdd + code-review) per ticket with /clear between -> pr -> retro. Keep the first three steps in one unbroken context window.

No adversarial skill

Proposals #633 (/review-spec) and #1051 (/red-team) were closed under the no-new-skills rule. His code-review is two axes, Standards and Spec, run in parallel and never merged or reranked.

03 · poteto

Verification is the bottleneck

No poteto/skills repo exists. The work lives in Cursor's pstack plugin, plus noodle, brainmaxxing, how, and a verification-skill example. She explicitly rejects planning skills.

"Most harnesses that have plan modes tend to over-specify implementation details and under-specify everything else. The truth is that I do plan, but I do so through code. I never bother with reviewing abstract plans adversarially. The agents start hallucinating theoretical risks."The Complete Guide to pstack, Pt. 2

interrogate

One reviewer per configured model family, same prompt and rubric: Correctness, Root Causes vs Symptoms, Structural Integrity, Verification, Complexity Budget, Security. Then lead judgment with anti-noise rules: Nitpick Gravity, Hypothetical vs Actual, I Would Have Done It Differently. "If your Act On list has more than 5 items, you're probably not filtering hard enough." The Dismissed section is a trust mechanism.

adversarial-review (noodle)

Reviewer count scales with diff size: Skeptic under 50 lines, plus Architect to 200, plus Minimalist above. Verdict PASS / CONTESTED / REJECT, then lead judgment. Reviewers must run through the other vendor's CLI.

blast-radius

A five-rung confidence ladder: "You said so. Worthless on its own." -> pointed at a line -> walked the failure -> ran it -> reproduced in the app. Prove "the one fact it's safe because of" by running code.

Trust ladder

Where to put a correction, most durable first: codebase > static analysis > rules > skills > style guides. /correct encodes it. "Textual instructions are routinely ignored. The instruction IS the symptom."

Shape

Almost every skill is disable-model-invocation: true and routed by one 20 KB /poteto-mode. Subagent prompts are separate template files. Every skill ends with a Reply: line. Phased skills open a todo list, one item per phase. Subagents get file pointers, not inlined context.

Human in the loop

"Never block on the human. Reserve confirmation for irreversible actions." Questions answerable by running something are not the human's to answer. The opposite pole from grilling.

04 · Scout

Chart the fog. Never build.

Scout is wayfinder with its seven known holes closed and the tracker fixed to GitHub issues. It runs before SPEC. Its output is a set of closed decisions that the SPEC phase consumes.

Invocation

/scout <loose idea> charts. /scout #<map> [#ticket] works one ticket. User-invoked only. It calls the Oracle primitive and research, prototype as model-invoked skills.

Hard stops

  • No write path to source. Research lands on a research/<name> branch with no PR.
  • Notes cannot grant execution. The only "do" is a scout:task ticket, and it still needs a human claim.
  • HITL tickets close only after a user line in the thread.
  • One ticket per session. Re-size on claim; split before resolving.

Labels

scout:map, scout:research, scout:prototype, scout:grill, scout:task. Blocking uses GitHub's native dependency links. Never a triage label.

Reopen

A closed decision reopens only with new evidence posted as a comment. Borrowed from contrarian's settled ledger. This fills the "wrong closed decision" hole.

Hand-off

Map clear -> the SPEC phase of the target package. Scout tells the user to open SPEC.md with the map link. AGENTS.md rule stays: ask before creating a SPEC.md that does not exist.

When not to use

If the first breadth-first round surfaces no fog, Scout stops and says so. Most dunky changes are one-session. Scout is for state-machine-sized moves: a new substrate, the Rust twin, a website redesign.

Pros
  • Memory lives in the tracker, not in context. Survives /clear and days away.
  • GitHub shows the frontier visually.
  • Research runs in parallel while you sleep.
  • Explicit out-of-scope list stops creep.
Cons
  • Waterfall drift past ~12 tickets. Cap the first chart.
  • Issue noise in small repos. Use one map per epic, close maps when done.
  • Needs the Oracle to be terse or charting becomes a wall of text.
05 · Oracle

The one that asks

Grilling-derived. Model-invoked primitive plus a one-line user wrapper. It never acts. It ends a round only when the frontier is empty and you confirm. One mismatch to settle first: an oracle answers, this agent asks.

Behavior contract

  • Frontier rounds. One sentence per question, one line per recommendation. Yes accepts the recommendation.
  • Facts are its job: it spawns a subagent and does not block. Decisions are yours.
  • Ends with the literal line Shared understanding reached. Confirm to continue. Scout and SPEC wait for that line. This closes wayfinder issue #1093.
  • Refers to things by name, never by ticket number.
  • Writes nothing. The same conversation flows into SPEC.

Where it fires

Scout charting. SPEC drafting. Before TEST when seams are unclear ("the ideal number of seams is one"). On RECONCILE when Red / Blue returns Needs Discussion. Always with you, never alone.

Support level

One wrapper, two intensities. /grill runs the full frontier. /grill --light asks only the questions whose answer changes the next action. The light mode is the one you will reach for mid-flow.

06 · Red / Blue

Tower defense at RECONCILE

The diff is the lane. Red is the wave: one attacker per equipped power, told "assume this is broken, find the concrete input that breaks it." Blue is the tower: one defender per claim, told "reproduce or refute, 'seems fine' is not a refutation." The gate scores survivors and writes the verdict. Toggle powers to see the wave.

Rules of engagement

Independence

Red and Blue never see the author's reasoning. They get the diff, the SPEC.md, the power file, and the stated intent. superpowers and devils-advocate both enforce this.

Concrete or nothing

A Red claim needs file:line and a failure path: input or state -> wrong output. A Blue refutation needs the same. Static inference caps at Important. Only a run or a reproduction earns Critical.

Gate

Per surviving claim, one scorer rates confidence 0 to 100 and drops under 80 (Anthropic code-review). Then lead judgment sorts into Act on, Consider, Dismissed, with the Dismissed list visible (poteto). Cap Act on at five.

Verdict words

Ship / Fix first / Needs discussion. Needs discussion hands to the Oracle. Fix first loops to IMPLEMENT. Ship ends RECONCILE.

Diversity

Default is mandate diversity, same model. Optional --cross runs Red on a second model family through its CLI. poteto's position: "the adversarial signal comes from model diversity, not assigned personas." Same-model agreement may be shared bias.

On specs

Not the full wave. Pocock closed /review-spec, poteto reports hallucinated risk. Specs get one power only, spec-completeness, with binary criteria: ambiguity, missing non-goals, untestable behavior. Borrowed from devils-advocate's 22-criteria plan check.

Sizing

Attackers per power scale with diff size: 1 under 50 lines, 2 to 200, 3 above. Blue is always one per claim. Cost note: agent-review-panel self-reports $3 to $20 a run with 69% in orchestrator turns. Keep the orchestrator thin.

The plug: powers

A power is one file: powers/<name>.md with a hunt list for Red, a refute list for Blue, and the sources it is derived from. The skill body holds only a routing table. Signal detection picks defaults: a diff touching packages/react equips a11y and design-system, a diff touching SPEC.md equips spec-completeness. You can always override with flags.

08 · Repo

Shape of this repository

Skills are markdown directories. The monorepo tooling here is useful for the scripts that powers call, not for the skills themselves. Skills follow the same four-phase loop as code.

skills/
  AGENTS.md                 # the contract, already here
  .claude-plugin/
    plugin.json             # installable via claude plugin / npx skills add
  skills/
    scout/
      SPEC.md               # intent, behavior contract, non-goals
      SKILL.md              # user-invoked, ~120 lines
      evals/                # pressure scenarios, RED before GREEN
    grill/                  # one-line wrapper over grilling
    grilling/               # model-invoked primitive
    red-blue/
      SKILL.md              # routing table + rules of engagement
      references/
        red-prompt.md       # attacker template, filled per power
        blue-prompt.md      # defender template
        gate-prompt.md      # scorer + lead judgment
      powers/
        spec-fidelity.md
        logic.md
        principles.md
        a11y.md
        ...                 # one file per power, see catalogue
    research/               # model-invoked, AFK, used by scout
    prototype/              # model-invoked, used by scout
  packages/
    skill-scripts/          # TS helpers a power may run (diff sizing, twin-parity check)
  research/
    skills-landscape.html   # this file

Loop for a skill

SPEC is the skill's SPEC.md. TEST is an eval scenario that fails without the skill (superpowers' RED baseline). IMPLEMENT is SKILL.md under 150 lines. RECONCILE is claude plugin eval plus /skill-doctor, and Red / Blue with the skill-quality power.

Conventions

  • Description is the trigger, never a summary of the workflow.
  • User-invoked skills set disable-model-invocation: true and call primitives by Skill tool name.
  • Every skill ends with a Reply: line.
  • References one level deep. No @ links.
  • Scripts for anything deterministic.

Changesets

Keep them. A skill is a public package to its consumers. A changed verdict word or a new power is a minor. A tightened prompt is a patch.

Open question

packages/core is a placeholder from the template. Either it becomes skill-scripts or it goes. ARCHITECTURE.md needs the dependency direction: skills may call scripts, scripts never read skills.
